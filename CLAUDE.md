# CLAUDE.md — правила работы в этом репозитории

Ты помогаешь строить риск-отчётность по кредитному портфелю: PostgreSQL → YAML-модель → Vega-Lite.
Цифры уходят на риск-комитет, поэтому правильность важнее скорости.

## Порядок работы

1. **Сначала профилируй данные, потом пиши SQL.** Перед любой метрикой проверь: дубли по (report_date, loan_id),
   полные и конфликтующие; переходы флагов между срезами (written_off, restructured); граничные значения
   days_past_due (30, 90); наличие курса на каждую дату среза; валюты без курса; остаток ≤ 0.
   Каждая найденная аномалия получает строку в `reporting.v_dq_checks` и упоминание в README.
2. **Определения бизнеса не переформулируй.** Они в README → «Определения». Если данные заставляют принять решение,
   которого нет в определении (пример — списание, «снятое» на следующем срезе), прими консервативное,
   задокументируй и посчитай влияние альтернативы.
3. **Каждую цифру проверяй вторым способом.** После изменения SQL запускай `./run.sh --local`;
   `tests/reconcile.py` должен закончиться «всё сошлось». Цифры в README переписывай из вывода запросов,
   а не на глаз из промежуточных таблиц.
4. **Дашборд проверяй глазами.** `python3 scripts/screenshot.py` и посмотри PNG (и `--dark`): обрезанные панели,
   пустые слои, дублирующиеся подписи осей. Консольные WARN от Vega — не шум, разбирайся.

## Правила SQL

* Только `CREATE SCHEMA IF NOT EXISTS`, `CREATE TABLE IF NOT EXISTS`, `CREATE OR REPLACE VIEW`. Загрузка — `TRUNCATE` + `\copy` в одной транзакции.
* `raw` — всё text, как в файле. Типизация, trim, дедупликация — в `reporting.v_loan_clean`.
* `CREATE OR REPLACE VIEW` не умеет удалять/переставлять колонки: новые колонки добавляй в конец, иначе — `DROP VIEW` вручную и отметь в коммите.
* Деньги — `numeric`, никогда `float`. Округление до копеек — построчно, перед суммированием.
* Курс — строго на дату среза; фолбэк на предыдущий день только с учётом в `v_dq_checks`.
* Доли считаются как отношение сумм, а не как avg флагов.

## Правила семантической модели

* Формат: `model`, `source: reporting.v_...`, `dimensions` (name, column, type, label), `measures` (name, column, type: sum/avg/count, format, label).
* Мера — только то, что корректно агрегируется в любом разрезе. Доли (PAR, NPL) и топ-N в модель не кладём: числитель и знаменатель — отдельными sum-мерами.
* После правки — `python3 tests/check_model.py`.

## Правила Vega-Lite

* Спеки — самодостаточные JSON в `dashboard/specs/`, данные по относительному `data/*.json`.
* Имена полей без точек (точка = вложенный путь) — особенно после `pivot`.
* Даты-строки не парсить в локальном времени (сдвиг дня в западных часовых поясах): подписи строим из строки.
* Цвет: 01.09 — нейтральный серый, 01.10 — синий акцент, одинаково на всех графиках. Без двойных осей.

## Нельзя

* Писать в README цифру, которой нет в выводе запроса.
* Молча «чинить» данные: любое исключение строк — через флаг во витрине и строку в `v_dq_checks`.
